# MyJob – Трекер поиска работы: спецификация проекта

## 1. Тема и проблема

**Тема:** персональный трекер поиска работы.

**Проблема.** Соискатель одновременно откликается на десятки вакансий. Информация о том, куда и когда отправлен отклик, ответил ли работодатель, когда назначено собеседование и кому нужно напомнить о себе, обычно разбросана по почте, мессенджерам, заметкам и таблицам. Из-за этого отклики теряются, собеседования накладываются друг на друга, а картина поиска в целом непонятна.

**Решение.** MyJob собирает все отклики в одном месте и показывает их статус, связанные собеседования и напоминания. Приложение считает статистику поиска (долю ответов, приглашений, предложений) и позволяет быстро найти нужный отклик.

## 2. Пользователь

Один пользователь: соискатель, который ведёт много откликов одновременно и хочет видеть текущее состояние поиска работы. Авторизации и совместной работы нет, данные хранятся локально в браузере.

## 3. Основная сущность: `JobApplication`

Один объект `JobApplication` – это **один отклик на одну конкретную вакансию**. Отклики составляют основную коллекцию приложения.

| Поле | Тип | Обязательное | Описание |
|---|---|---|---|
| `id` | строка | да | Уникальный идентификатор отклика |
| `company` | строка | да | Название компании |
| `position` | строка | да | Должность |
| `description` | многострочный текст | да | Описание вакансии (допускается пустая строка) |
| `categoryId` | строка | да | Идентификатор категории вакансии (ссылка на `Category`) |
| `status` | `applied` \| `viewed` \| `interview` \| `offer` \| `rejected` \| `withdrawn` | да | Текущий статус отклика |
| `salary` | число | да | Зарплатные ожидания (нижняя граница) |
| `salaryMax` | число | нет | Верхняя граница зарплатных ожиданий |
| `currency` | `RUB` \| `USD` \| `EUR` | да | Валюта, по умолчанию `RUB` |
| `appliedAt` | дата (ISO) | да | Дата отправки отклика |
| `createdAt` | дата и время (ISO) | да | Дата и время создания записи в приложении |
| `updatedAt` | дата и время (ISO) | да | Дата и время последнего изменения записи |
| `employmentType` | `full-time` \| `part-time` \| `internship` \| `contract` | да | Тип занятости |
| `workFormat` | `remote` \| `hybrid` \| `office` | да | Формат работы |
| `jobUrl` | строка | да | Ссылка на вакансию (допускается пустая строка) |
| `contactEmail` | строка | да | Контактный e-mail (допускается пустая строка) |
| `notes` | многострочный текст | да | Заметки пользователя (допускается пустая строка) |
| `isFavorite` | логическое | да | Признак избранного |
| `isArchived` | логическое | да | Признак архивирования (запись не удаляется физически) |

`appliedAt` – это дата, когда пользователь отправил отклик. `createdAt` – момент, когда запись появилась в приложении. Эти поля не совпадают: отклик, отправленный неделю назад, можно внести сегодня.

### Статусы

| Статус | Значение | Цвет индикатора |
|---|---|---|
| `applied` | Отклик отправлен | синий |
| `viewed` | Отклик просмотрен работодателем | голубой |
| `interview` | Собеседование | фиолетовый |
| `offer` | Получено предложение | зелёный |
| `rejected` | Получен отказ | красный |
| `withdrawn` | Отклик отозван | серый |

Переходы между статусами не обязаны быть последовательными: например, из `applied` можно сразу перейти в `rejected`.

## 4. Связанные сущности

Связанные сущности ссылаются на отклик через `applicationId`, а не содержат копию отклика.

| Сущность | Назначение | Основные поля |
|---|---|---|
| `Category` | Категория вакансии | `id`, `name`, `color` |
| `Interview` | Собеседование по отклику | `id`, `applicationId`, `title`, `type`, `date`, `time`, `format` (`online` \| `offline` \| `phone`), `location?`, `meetingUrl?`, `contactPerson?`, `notes` |
| `FollowUp` | Напоминание связаться с работодателем | `id`, `applicationId`, `title`, `description`, `dueDate`, `isCompleted` |
| `StatusHistory` | История смены статусов | `id`, `applicationId`, `previousStatus` (или `null` для первого), `newStatus`, `changedAt`, `comment?` |
| `ActivityLog` | Журнал действий с данными | `id`, `applicationId?`, `type`, `action`, `description`, `createdAt` |

Связи: одна категория относится ко многим откликам; к одному отклику относятся много собеседований, напоминаний и записей истории статусов; записи журнала действий могут быть привязаны к отклику (`applicationId`), а могут относиться ко всему приложению (например, импорт данных).

### Допустимые значения `ActivityLog.type`

Тип события – закрытый набор значений:

`created`, `updated`, `deleted`, `archived`, `restored`, `status_changed`, `note_added`, `interview_added`, `interview_updated`, `interview_deleted`, `follow_up_added`, `follow_up_completed`, `follow_up_deleted`, `data_imported`, `data_exported`, `data_cleared`.

### Форматы данных

- Интерфейс полностью на русском языке.
- Внутри приложения даты хранятся в формате ISO 8601; пользователю они показываются в формате **ДД.ММ.ГГ** (например, 14.11.26).
- Первый день недели в календаре – понедельник.
- Допустимые валюты: RUB (по умолчанию), USD, EUR.
- Приложение поддерживает светлую и тёмную темы оформления.

## 5. Действия с основной сущностью

- создание отклика;
- просмотр списка и подробной информации;
- редактирование отклика;
- изменение статуса с сохранением истории переходов;
- добавление в избранное и удаление из избранного;
- архивирование и возврат из архива;
- удаление с подтверждением;
- добавление, изменение и удаление собеседований, связанных с откликом;
- создание напоминаний follow-up и отметка об их выполнении;
- поиск по компании, должности и описанию;
- фильтрация по статусу, категории, формату работы, типу занятости (несколько фильтров одновременно) и сброс фильтров;
- сортировка по дате отклика, компании, должности и зарплате;
- импорт и экспорт данных в формате JSON;
- очистка локальных данных с подтверждением.

## 6. Страницы приложения

Каждая страница – отдельный маршрут со своим URL. Всего восемь страниц.

### 6.1. Dashboard

- **URL:** `/`
- **Назначение:** быстро показать текущее состояние поиска работы.
- **Отображаемые данные:** общее количество откликов, количество активных процессов отбора, полученные предложения и отказы, ближайшие собеседования, последние добавленные отклики, динамика откликов, диаграмма по статусам.
- **Действия пользователя:** перейти к отклику из списка последних откликов или ближайших собеседований, перейти к созданию отклика, списку откликов и календарю.

### 6.2. Все отклики

- **URL:** `/applications`
- **Назначение:** работа со всей коллекцией откликов.
- **Отображаемые данные:** список откликов (компания, должность, категория, дата отклика, зарплатные ожидания, статус, признак избранного), активные фильтры, количество найденных записей.
- **Действия пользователя:** поиск, фильтрация, сортировка, переключение представления списка, добавление в избранное, смена статуса, архивирование, удаление, переход к подробной информации, редактированию и созданию отклика. Если откликов нет, отображается пустое состояние; если поиск и фильтры ничего не нашли, – состояние «ничего не найдено» со сбросом фильтров.

### 6.3. Подробная информация об отклике

- **URL:** `/applications/:id`
- **Назначение:** показать всё об одном отклике.
- **Отображаемые данные:** компания, должность, описание вакансии, категория, статус, зарплата и валюта, формат работы, тип занятости, дата отклика, ссылка на вакансию, контактный e-mail, заметки, история смены статусов, связанные собеседования и напоминания. Если запись не найдена или архивирована, отображается соответствующее состояние.
- **Действия пользователя:** изменить статус, добавить в избранное, перейти к редактированию, архивировать и удалить отклик, добавить, изменить и удалить собеседование, создать напоминание и отметить его выполненным, открыть ссылку на вакансию.

### 6.4. Создание отклика

- **URL:** `/applications/new`
- **Назначение:** добавить новый отклик.
- **Отображаемые данные:** форма с полями компании, должности, описания, категории, зарплаты, валюты, формата работы, типа занятости, ссылки на вакансию, контактного e-mail, даты отклика и заметок; сообщения об ошибках валидации.
- **Действия пользователя:** заполнить форму, сохранить отклик, отменить создание. Некорректные данные сохранить нельзя.

### 6.5. Редактирование отклика

- **URL:** `/applications/:id/edit`
- **Назначение:** изменить существующий отклик.
- **Отображаемые данные:** та же форма, что и при создании, предзаполненная текущими данными записи; состояние «запись не найдена» для несуществующего идентификатора.
- **Действия пользователя:** изменить поля, сохранить изменения, отменить редактирование.

### 6.6. Статистика и аналитика

- **URL:** `/analytics`
- **Назначение:** показать результаты поиска работы в цифрах.
- **Отображаемые данные:** общее и активное количество откликов, количество полученных ответов, собеседований, предложений и отказов, процент ответов работодателей, процент приглашений на собеседование, конверсия из отклика в предложение, динамика отправленных откликов по месяцам, распределение по статусам и по категориям. Все показатели вычисляются из реальных данных приложения.
- **Действия пользователя:** просматривать показатели и диаграммы, переходить к списку откликов.

### 6.7. Календарь

- **URL:** `/calendar`
- **Назначение:** планирование собеседований и последующих действий.
- **Отображаемые данные:** календарная сетка месяца (неделя с понедельника), собеседования и напоминания follow-up по датам, список событий выбранного дня.
- **Действия пользователя:** переключаться между месяцами, выбирать день, переходить к отклику, к которому относится событие, отмечать напоминания выполненными.

### 6.8. Настройки

- **URL:** `/settings`
- **Назначение:** управление данными приложения.
- **Отображаемые данные:** основные параметры приложения, объём сохранённых данных, результат последнего импорта (количество принятых и отклонённых записей).
- **Действия пользователя:** экспортировать данные в JSON, импортировать данные из JSON-файла, очистить локальные данные с подтверждением.

### Соответствие обязательным типам страниц задания

| Тип страницы по заданию | Страница MyJob |
|---|---|
| Обзор / Dashboard | `/` |
| Список сущностей | `/applications` |
| Подробная информация | `/applications/:id` |
| Создание и редактирование | `/applications/new`, `/applications/:id/edit` |
| Статистика, история, аналитика | `/analytics` |
| Дополнительная страница, важная для темы | `/calendar` (собеседования и follow-up), `/settings` (импорт, экспорт, очистка) |

## 7. Пользовательские сценарии

### Сценарий 1. Добавить отклик на вакансию

1. Пользователь открывает список откликов и нажимает «Добавить отклик».
2. Заполняет форму: компания, должность, категория, зарплата, валюта, формат работы, тип занятости, дата отклика.
3. Оставляет поле с названием компании пустым и видит сообщение об обязательном поле.
4. Исправляет ошибку и сохраняет отклик.
5. Приложение возвращает пользователя в список, новый отклик отображается со статусом «Отклик отправлен» и остаётся после перезагрузки страницы.

### Сценарий 2. Пригласили на собеседование

1. Пользователь открывает подробную информацию об отклике.
2. Меняет статус на «Просмотрен», затем на «Собеседование».
3. Добавляет собеседование: дата, время, формат, этап, ссылка на видеоконференцию.
4. Открывает календарь и находит собеседование в нужный день.
5. Переходит из календаря обратно к отклику; в истории статусов видны обе смены статуса с датами.

### Сценарий 3. Найти приоритетные вакансии

1. Пользователь открывает список откликов и вводит часть названия компании в поиск.
2. Выбирает фильтры по статусу и категории и сортирует результат по зарплате по убыванию.
3. Добавляет подходящие отклики в избранное.
4. Включает показ только избранного и видит приоритетные вакансии.
5. Сбрасывает все фильтры и возвращается к полному списку.

### Сценарий 4. Получить предложение или отказ

1. Пользователь получает ответ от работодателя и открывает отклик.
2. Меняет статус на «Предложение» (или «Отказ») и добавляет комментарий.
3. Статус обновляется в списке и на странице отклика, запись появляется в истории статусов.
4. Пользователь открывает страницу аналитики и видит обновлённые количество предложений (отказов), процент ответов и конверсию.
5. Отклик с отказом пользователь архивирует: он исчезает из основного списка, но остаётся доступным по прямой ссылке.

### Сценарий 5. Сохранить и восстановить данные

1. Пользователь открывает настройки и выгружает данные в JSON-файл.
2. Нажимает «Очистить данные» и подтверждает действие в диалоге; приложение показывает пустое состояние.
3. Выбирает ранее сохранённый файл в разделе импорта.
4. Приложение проверяет структуру файла и сообщает, сколько записей импортировано и отклонено.
5. После импорта отклики, собеседования и напоминания снова доступны во всех разделах.

## 8. Что не входит в первую версию

- реальный серверный backend и серверная база данных (используются mock-данные, mock API на Promise и localStorage);
- регистрация, авторизация и несколько пользователей;
- синхронизация данных между устройствами и браузерами;
- автоматический импорт вакансий с сайтов поиска работы и разбор ссылок на вакансии;
- уведомления по e-mail, push-уведомления и синхронизация с внешними календарями;
- загрузка резюме, сопроводительных писем и других файлов;
- совместная работа и общий доступ к данным;
- мобильное приложение и работа без браузера;
- автоматические тесты (проверка выполняется вручную и командой `npm run build`);
- интерфейс на языках, кроме русского.
